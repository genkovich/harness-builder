# Harness Builder

Репозиторій другого дня воркшопу «LLM Harness». Тут ми з нуля, етап за етапом, пишемо власний харнес для агента на TypeScript. Із бібліотек беремо лише AI SDK (`ai`), щоб говорити з моделлю, і grammY для Telegram. Цикл, тули, ліміти, повтори, памʼять розмови і дозволи на тули пишемо самі. Агент робить справжню роботу: це Telegram-бот нотаток. Він зберігає нотатки, шукає їх, памʼятає розмову в кожному чаті й складає стендап. Поруч у браузері працює візуальний харнес: зліва чат, справа наживо кожен крок циклу, з тим, що пішло в модель і що вона повернула.

## Домашка до дня 2

Зроби це вдома. Якщо Node уже стоїть, вистачить десяти хвилин.

### 1. Node і Git

Потрібен Node 22.19+ або 24.11+.

```bash
node --version
git --version
```

Версія нижча: постав свіжу з [nodejs.org](https://nodejs.org) або через `nvm install 24`.

### 2. Клонуй і встанови

```bash
git clone https://github.com/genkovich/harness-builder.git
cd harness-builder
npm ci
```

`npm ci` ставить залежності з `package-lock.json`, а скрипт `prepare` одразу копіює `.env.example` у `.env`. Якщо `.env` уже є, його не чіпає. Файл `.env` у git не потрапляє.

Після клонування ти на `main`, там фінальний код усіх етапів, те саме, що `step-10`. На занятті почнемо з `npm run step 00`.

### 3. Ключ моделі

Типово працюємо з Qwen 3.8 на Groq Free. Ключ безкоштовний: зайди на [console.groq.com/keys](https://console.groq.com/keys), створи ключ і встав його в `.env`:

```bash
MODEL=groq/qwen/qwen3.8-27b
GROQ_API_KEY=gsk_...
```

Можна взяти іншого провайдера. Зміни `MODEL` і заповни лише ключ цього провайдера:

| Провайдер | `MODEL` | Ключ |
|---|---|---|
| Groq Free | `groq/qwen/qwen3.8-27b` | `GROQ_API_KEY` |
| OpenAI | `openai/gpt-4.1-mini` | `OPENAI_API_KEY` |
| Anthropic | `anthropic/claude-haiku-5-5` | `ANTHROPIC_API_KEY` |
| OpenRouter | `openrouter/qwen/qwen3-32b` | `OPENROUTER_API_KEY` |

`MODEL` має формат `провайдер/модель`. Код ділить рядок лише по першому `/`, тож у `groq/qwen/qwen3.8-27b` провайдер `groq`, а назва моделі `qwen/qwen3.8-27b`.

Ведучий показує все на OpenAI. Ціни харнес знає лише для `openai/gpt-4.1-mini` і `openai/gpt-4.1`. На Groq Free вартість завжди нуль. Для інших моделей у trace буде «н/д», поки не задаси в `.env` свою ціну за 1 млн токенів: `PRICE=вхід,кеш,вихід`, наприклад `PRICE=0.4,0.1,1.6`.

### 4. Telegram-бот

1. Відкрий [@BotFather](https://t.me/BotFather) і надішли `/newbot`.
2. Придумай назву і username, який закінчується на `bot`.
3. BotFather пришле токен виду `123456789:AA...`. Встав його в `.env`:

```bash
TELEGRAM_BOT_TOKEN=123456789:AA...
```

Токен дає повний контроль над ботом, у чати його не кидай. Бота краще створити вдома: коли три десятки людей реєструють ботів з одного Wi-Fi, Telegram може тимчасово заблокувати реєстрацію.

`OWNER_CHAT_ID` поки лишай порожнім, він знадобиться на етапі 09.

### 5. Перевірка

```bash
npm run doctor
```

Doctor робить справжні запити: один короткий запит до моделі і `getMe` у Telegram. Ще дивиться версію Node, чи є `.env` і чи вільний порт. Має вийти щось таке, числа будуть свої:

```text
✓ Node 24.11.0
✓ .env є
✓ модель groq/qwen/qwen3.8-27b відповіла за 640 мс (in 14, out 3)
✓ Telegram-бот @твій_бот
✓ порт 3000 вільний

Усе готово до заняття.
```

Без токена Telegram doctor ставить жовтий `!` і наприкінці пише «Етапи 00-05 готові. Додай токен бота, він потрібен з етапу 06.» На заняття приходь уже з рядком `✓ Telegram-бот` і «Усе готово до заняття».

## Як іде заняття

Кожен етап лежить в окремій гілці `step-00` … `step-10`. Ведучий пише код етапу наживо. Ти перемикаєшся на готову гілку й дивишся, що змінилось:

```bash
npm run step 03
```

Скрипт спершу робить `git fetch`, тож якщо ведучий виправив етап посеред заняття, ти отримаєш свіжу версію. Далі ховає твої незакомічені правки в `git stash` з підписом «мої правки перед step-03», перемикає на гілку етапу, друкує його назву і diff від попереднього етапу, а наприкінці запускає тести цього етапу. `npm run step` без номера покаже, на якому ти етапі, і список усіх.

`npm run web` не стежить за файлами. Після кожного `npm run step` зупини його (Ctrl+C) і запусти знову:

```bash
npm run web
```

Відкрий http://localhost:3000. Пиши задачу в чат зліва, справа зʼявиться запуск і кроки циклу. `.env`, `.data/` і `node_modules` git не чіпає, тож ключі, trace, нотатки й історія чатів переживають перемикання етапів.

### Хочеш написати етап сам

Зроби свою гілку від попереднього етапу і підтягни тести наступного:

```bash
git switch -c my-03 origin/step-02
git checkout origin/step-03 -- test/03-tools.test.mjs
npm test -- --step 03
```

У гілках `step-NN` нічого не коміть: `npm run step` щоразу перестворює їх з `origin`, і твій коміт зникне з гілки.

## Команди

| Команда | Що робить |
|---|---|
| `npm run web` | Веб-харнес на http://localhost:3000. З етапу 06 у тому самому процесі ще й Telegram, якщо задано `TELEGRAM_BOT_TOKEN` |
| `npm run cli -- "задача"` | Одна задача з термінала, короткий рядок на кожну подію. Повний trace у `.data/trace-cli.jsonl` |
| `npm run step NN` | Перейти на етап NN: diff від попереднього і тести етапу |
| `npm test` | Усі тести, що є в поточній гілці. Без мережі: модель скриптована, Telegram API перехоплений, нотатки й історія пишуться в тимчасову теку |
| `npm test -- --step NN` | Лише тести етапу NN |
| `npm run doctor` | Перевірка перед заняттям |
| `npm run check` | Перевірка типів, `tsc --noEmit` |

CLI запускається окремим процесом, але веб-харнес стежить за його файлом trace у `.data/`. Тому запуски з термінала видно у вебі наживо, поруч із запусками з браузера й Telegram.

Події trace й поля кожної описані в [docs/trace-events.md](docs/trace-events.md).

## Що лежить у `.data/`

| Файл | З якого етапу | Що там |
|---|---|---|
| `.data/trace-<канал>.jsonl` | 00 | Події trace: `web`, `telegram`, `cli` |
| `.data/notes.json` | 02 | Нотатки всіх чатів, у кожної свій `chatId` |
| `.data/history/<chatId>.json` | 07 | Історія розмови одного чату |

Хочеш почати з чистого аркуша: зупини `npm run web` і видали потрібний файл.

## Якщо не так

**`Telegram 409 Conflict: з цим токеном запущено ще один процес`.** Telegram тримає одне зʼєднання на токен. Коли стартує другий процес з тим самим токеном (другий `npm run web`, старий бот з іншого репо, той самий бот на іншій машині), він перехоплює повідомлення, а перший отримує 409 і зупиняється назавжди. Зупини зайвий процес і перезапусти той, що лишився. Telegram віддає повідомлення лише одному слухачу.

**`Telegram 401: токен неправильний`.** Скопіюй токен з BotFather ще раз, без пробілів і лапок, або візьми новий через `/token`.

**Groq 429.** На Groq Free є ліміт запитів і токенів на хвилину. З етапу 05 харнес сам чекає стільки, скільки просить заголовок `Retry-After`, і пробує ще до двох разів, але не довше 30 секунд за раз. У trace це видно як «Повтор». До етапу 05 повтори робить сам AI SDK, і в trace їх не видно. Якщо не допомогли, запуск падає: у чаті «Сервер не прийняв задачу. HTTP 500: ...» з причиною від провайдера. Зачекай хвилину й пиши рідше.

**`Request too large`.** Groq Free рахує в хвилинний ліміт увесь запит: вхід разом із зарезервованим виходом `max_tokens`. Такий запит не пройде і з другої спроби, тому харнес його не повторює і зупиняється з причиною «помилка». Тому ж у коді стоїть `maxOutputTokens: 1_000`: з більшим значенням Groq Free запит не приймає. З етапу 07 у кожен запит іде ще й історія чату, до 40 останніх повідомлень. Якщо розмова розрослась, видали `.data/history/<chatId>.json` або візьми у веб-чаті інший `chat id`.

**Нічого не змінилось після `npm run step`.** Перезапусти `npm run web`: процес досі виконує код попереднього етапу.

**Червоні рядки doctor:**

| Що бачиш | Що зробити |
|---|---|
| `Node … застарий` | Постав Node 22.19+ або 24.11+ |
| `.env немає` | `cp .env.example .env` або `npm run prepare`. На Windows перевір, що файл не називається `.env.txt` |
| `GROQ_API_KEY порожній для MODEL=…` | Встав ключ у `.env`. Назва змінної залежить від провайдера в `MODEL` |
| `модель не відповіла: …` | Перевір `MODEL` і ключ. На Groq Free після 429 почекай хвилину. Сюди ж падають `MODEL має бути у форматі провайдер/модель` і `Невідомий провайдер` |
| `Telegram не прийняв токен` | Візьми новий токен у @BotFather (`/token`) |
| `порт 3000 зайнятий` | Зупини інший процес або постав `PORT=3001` у `.env` |
