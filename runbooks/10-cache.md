# 10. Кеш і інструкції: AGENTS.md, стабільний префікс

[Усі етапи](README.md) · [Попередній](09-permissions.md)

**Гілка:** `step-10`, останній етап, те саме, що `main`. Перейти: `npm run step 10`, далі перезапусти `npm run web`.

## Що додаємо і навіщо

Дві зміни. Перша про інструкції, друга про гроші.

Досі вся інструкція агента жила в коді, у `system` з `src/agent.ts`. Тепер правила бота лежать ще й у файлі `AGENTS.md`: як звертатись до користувача, що Telegram не показує markdown, як відповідати після збереження нотатки. Цей файл може правити людина без знання TypeScript, і його зміни видно в git. Харнес читає `AGENTS.md` на старті і кладе в `system` у тегу `<project source="AGENTS.md">`.

Друга зміна про кеш. Кожен крок харнес шле моделі все наново: `system`, схеми тулів, історію чату. Провайдери вміють кешувати початок запиту, якщо він однаковий байт у байт, і кешовані токени коштують дешевше. З етапу 07 у запиті є історія, і вона росте. Для кешу це якраз добре: наступний запит у тому ж чаті мав би починатися з того самого, що й попередній.

Але на етапі 08 ми поставили поточний час у кінець `system`. `system` іде в запиті першим, тож він різний щоразу, і кеш ламається на першому ж байті. Тепер час переїжджає в кінець нового повідомлення користувача, у тег `<now>…</now>`. `system`, тули, `AGENTS.md` і вся минула історія однакові байт у байт, а все змінне стоїть у самому кінці.

OpenAI і Groq кешують префікс самі, без змін у запиті. Anthropic кешує лише до позначки `cacheControl`. Ставимо її на останнє повідомлення запиту, тоді в кеш іде все перед ним. Позначку не зберігаємо в історію: інакше вони накопичувались би з кожним запуском, а Anthropic приймає до чотирьох. Інші провайдери цю позначку просто ігнорують.

Кеш видно в trace як `usage.cacheRead`. Якщо провайдер цього числа не повідомив, веб-харнес пише «провайдер не повідомляє кеш». Groq часто саме так і робить.

Ще в trace зʼявляється подія `context`: оцінка, скільки токенів займає `system`, кожен тул цього чату, кожна секція і історія. Права панель «Контекст» у веб-харнесі нарешті оживає.

## Код

### Інструкції проєкту: `AGENTS.md`

```md
# Бот нотаток

Ти особистий асистент у Telegram і у веб-чаті. Відповідай українською, коротко, на «ти».
Telegram показує простий текст: без markdown-таблиць, без заголовків з «#», без жирного.
Коли зберіг нотатку, скажи одним реченням, що саме зберіг.
Якщо нотаток немає, так і скажи. Не вигадуй того, чого немає в нотатках чи в розмові.
```

### Читаємо файл: `src/context.ts`

```ts
// Інструкції проєкту з AGENTS.md. Файл не змінюється між задачами, тож лежить у стабільному префіксі запиту.
export function loadContext(root = new URL('../', import.meta.url)): Section[] {
  return [{ tag: 'project', source: 'AGENTS.md', text: readFileSync(new URL('AGENTS.md', root), 'utf8') }];
}
```

У `src/agent.ts`: `context: [...loadContext(), skillCatalog()]`. Спершу `AGENTS.md`, потім каталог skills, завжди в цьому порядку.

### System без часу: `src/harness.ts`

```ts
// System = інструкції агента + файли проєкту. Між задачами він однаковий байт у байт,
// тож разом зі списком тулів і історією чату це стабільний префікс, який провайдер бере з кешу.
function systemOf(agent: Agent) {
  return [agent.system, ...(agent.context ?? []).map(renderSection)].join('\n\n');
}

// Час міняється щозапиту, тому стоїть у самому кінці, після всього стабільного.
// У історію повідомлення йде саме таким, тож наступний запит почнеться з тих самих байтів.
function userMessage(task: string): ModelMessage {
  return { role: 'user', content: `${task}\n\n<now>${new Date().toISOString()}</now>` };
}
```

Повідомлення з `<now>` іде в історію без змін. Наступний запуск підвантажить його точно таким, яким воно пішло в модель минулого разу. Якби ми додавали час лише в запит, а в історію клали чисте повідомлення, префікс знову розійшовся б.

### Позначка кешу лише на останньому

```ts
// Anthropic кешує лише до позначки cacheControl. Ставимо її на останнє повідомлення запиту
// і не зберігаємо в історію: інакше позначки накопичувались би (Anthropic приймає до чотирьох).
// OpenAI і Groq кешують префікс самі, без позначок.
function markCache(messages: ModelMessage[]): ModelMessage[] {
  const last = messages.at(-1);
  if (!last) {
    return messages;
  }
  return [...messages.slice(0, -1), { ...last, providerOptions: { anthropic: { cacheControl: { type: 'ephemeral' } } } }];
}
```

`markCache` повертає новий масив для `generateText`. Масив `messages`, який потім іде в історію, лишається без позначок.

### Ціна з кешем: `src/model.ts`

```ts
return ((input - cached) * price.input + cached * price.cachedInput + output * price.output) / 1_000_000;
```

Для `gpt-4.1-mini` кешований токен коштує $0.10 за мільйон проти $0.40 за звичайний.

### Як OpenAI рахує кеш

Це видно з живого прогону на `gpt-4.1-mini`. OpenAI кешує префікс лише від 1024 токенів, а далі сходинками по 128. Тому `cacheRead` у trace завжди одне з чисел 1024, 1152, 1280 і так далі, і ніколи не 1089.

З кешу береться префікс, який уже був у попередньому запиті. Якщо попередній запит мав 1089 токенів, у кеш потрапило лише 1024: до наступної сходинки, 1152, він не дотягнув. Решта 65 токенів наступного разу знову рахуються за повною ціною.

Тепер зрозуміло, що ламав час у `system`. На етапах 08 і 09 перший крок кожного нового запиту давав `cacheRead` 0, хоч яка довга була розмова. `system` іде першим, а в його кінці стояв `Current time`, тож префікс розходився вже на першому повідомленні. На етапі 10 той самий чат, коли розмова переросла приблизно 1100 токенів, уже на першому кроці дає кеш. Приклад з прогону: `input` 1156, `cacheRead` 1024.

## Спробуй

- Надішли будь-яку задачу й подивись на панель «Контекст» справа: `system`, кожен тул, секції `<project>` і `<skills>`, історія чату, з оцінкою токенів. Оцінка груба, символи поділені на 4. Точне число на першому кроці дає провайдер у `usage.input`, і воно більше: туди ще входять задача і JSON-схеми тулів.
- Розгорни «Запит до моделі»: у `system` видно `<project source="AGENTS.md">`, а час тепер у кінці останнього повідомлення, у `<now>`.
- Допиши в `AGENTS.md` рядок «Наприкінці кожної відповіді додай рядок "Перевірено харнесом"», перезапусти `npm run web` і спитай щось. Прибери рядок після цього.
- Кеш, на `openai/gpt-4.1-mini`. Веди розмову в одному чаті: зберігай нотатки, питай про них. Після кожного повідомлення дивись у відповіді моделі на бейджі «вхід» і «кеш» або на лічильник «кеш прочитано» угорі. Поки «вхід» менший за ~1100 токенів, кеш на першому кроці 0. Коли перевалить, зʼявиться 1024, а далі 1152, 1280 у міру того, як росте розмова. Кеш видно й на другому кроці однієї задачі, коли модель викликала тул: там префікс уже містить перший крок. На Groq побачиш «провайдер не повідомляє кеш», це нормально.
- Хочеш побачити, що саме дав перенос часу: тим самим чатом пройди етап 09 (`npm run step 09`, перезапусти `npm run web`). Хоч яка довга розмова, на першому кроці кеш 0.
- Порівняй сирі запити двох повідомлень одного чату («сирий HTTP-запит до провайдера»). Початок однаковий аж до нового повідомлення.

## Перевірка

```bash
npm test -- --step 10
```

- `10 AGENTS.md іде в system, у trace видно, скільки займає кожна частина`: `<project source="AGENTS.md">` у `system`, подія `context` з секцією `AGENTS.md` і тулами.
- `10 префікс запиту однаковий байт у байт: system, тули, історія`: два запуски в одному чаті, однаковий `system` без дати, однакові тули, перше повідомлення другого запуску збігається з першим, `<now>` у самому кінці нового.
- `10 позначка кешу для Anthropic лише на останньому повідомленні запиту і не в історії`: у другому запуску рівно одна позначка, і вона на останньому повідомленні.
- `10 cache read з usage видно в trace, і він здешевлює запит`: 1536 кешованих токенів з 2000 рахуються за ціною кешу.

## Якщо не так

- Зміна в `AGENTS.md` не діє: файл читається, коли створюється агент, тобто на старті. Перезапусти `npm run web`.
- Панель «Контекст» досі пише «Зʼявиться на етапі 10»: ти дивишся на старий запуск. Надішли нову задачу.
- Кеш завжди нуль на OpenAI: префікс коротший за 1024 токени, розмову треба вести далі в тому ж чаті. Або щось у префіксі міняється між запитами: порівняй сирі запити двох повідомлень у trace.
- `cacheRead` менший, ніж ти чекав, наприклад 1024 при вході 1150: так і має бути. OpenAI кешує сходинками по 128 токенів і бере лише те, що було в попередньому запиті.
- Модель плутає дату: час у `<now>` в UTC, з `Z` наприкінці. Якщо треба місцевий час, це правка в `userMessage`.
