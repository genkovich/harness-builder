# 07. Памʼять розмови: історія кожного чату

[Усі етапи](README.md) · [Попередній](06-telegram.md) · [Наступний](08-skill.md)

**Гілка:** `step-07`. Перейти: `npm run step 07`, далі перезапусти `npm run web`.

## Що додаємо і навіщо

Досі кожне повідомлення було окремою задачею. Пишеш «Мене звати Оля», потім «Як мене звати?», і бот не знає. Модель тут ні до чого: вона бачить лише масив `messages`, а харнес щоразу клав туди одне нове повідомлення.

Памʼять розмови робимо самі, і це звичайний файл. Після кожного запуску харнес дописує в `.data/history/<chatId>.json` усе, що сталося: повідомлення користувача, виклики тулів, їхні результати і фінальну відповідь. Перед наступним запуском у тому ж чаті підвантажує цей файл і ставить нове повідомлення в кінець. Модель отримує всю розмову і «памʼятає».

Ключ памʼяті = `chatId`. У кожного чату свій файл, тож сусід, який пише тому самому боту, твоєї розмови не бачить. Перезапуск процесу памʼять не стирає.

Історія росте, а запит не гумовий. Тому в запит іде не більше 40 останніх повідомлень. І тут закриваємо ще один баг каркаса з дня 1. Там компакція брала хвіст історії, і він міг початися з результату тула без його виклику. Провайдер такий запит відхиляє. Ми ріжемо лише перед повідомленням користувача. Обмін «питання, виклик тула, результат, відповідь» або йде в запит цілим, або не йде зовсім, і пара виклик-результат не рветься.

`chatId` у веб-чаті ти вписуєш руками, а він стає частиною імені файла. Тому в імені лишаємо лише безпечні символи, і `../../щось` за межі теки не вийде.

## Код

### Історія у файлі: `src/history.ts`

```ts
// Памʼять розмови: усі повідомлення чату лежать у файлі й переживають перезапуск.
// Модель сама нічого не памʼятає. Що код не поклав у запит, того вона не бачить.
export const maxHistoryMessages = 40;

// chatId у вебі задає користувач. У назві файла лишаємо лише безпечні символи,
// інакше «../../щось» вийшло б за межі теки.
function historyFile(chatId: string) {
  return join(historyDir(), `${chatId.replace(/[^\w-]/g, '_')}.json`);
}
```

`historyDir()` бере `HISTORY_DIR` з оточення, типово `.data/history`. Тести підставляють свою теку.

```ts
try {
  return JSON.parse(readFileSync(file, 'utf8'));
} catch (error) {
  // Зіпсований файл не має валити кожен запуск цього чату. Відкладаємо його вбік і починаємо з чистої історії.
  const broken = `${file}.broken-${Date.now()}`;
  renameSync(file, broken);
  console.error(`Історія чату ${chatId} не читається (${error instanceof Error ? error.message : error}), відклав у ${broken}.`);
  return [];
}
```

Файл історії можна відкрити й поправити руками, а отже і зламати. Без цього `catch` один зіпсований файл валив би кожен запуск свого чату. Файл лишається поруч під іншою назвою, тож розмову ще можна врятувати.

### Обрізання по межах обміну

```ts
// Старі повідомлення відкидаємо, але ріжемо лише перед повідомленням користувача.
// Так tool result ніколи не лишиться без свого tool call: пара живе в межах одного обміну.
export function trimHistory(messages: ModelMessage[], max = maxHistoryMessages) {
  if (messages.length <= max) {
    return { messages, trimmed: 0 };
  }
  let start = messages.findIndex((message, index) => index >= messages.length - max && message.role === 'user');
  if (start < 0) {
    // В останніх max повідомленнях немає жодного user: беремо останній обмін цілим, навіть якщо він довший.
    start = messages.map(message => message.role).lastIndexOf('user');
  }
  if (start < 0) {
    return { messages: [], trimmed: messages.length };
  }
  return { messages: messages.slice(start), trimmed: start };
}
```

Шукаємо перше повідомлення користувача серед останніх 40 і беремо все від нього. Тож у запит може піти й менше за 40, зате завжди цілими обмінами.

### Підвантажити перед, дописати після: `src/harness.ts`

```ts
// Памʼять розмови: спершу минулі повідомлення цього чату, нове повідомлення в кінці.
const history = loadHistory(where.chatId);
const kept = trimHistory(history);
// Уся «памʼять» моделі = цей масив. Що в нього не поклали, того вона не бачить.
const messages: ModelMessage[] = [...kept.messages, { role: 'user', content: task }];

const stop = (reason: StopReason, text: string): RunResult => {
  // Користувач бачив цей текст, тож і в історії він має бути. Фінальна відповідь моделі вже в messages.
  if (reason !== 'final') {
    messages.push({ role: 'assistant', content: text });
  }
  saveHistory(where.chatId, messages);
  trace('stop', { reason, text, turns: turn, costUsd: cost });
  return { runId: run.runId, reason, text, turns: turn, costUsd: cost, messages };
};
```

Зберігаємо в одному місці, у `stop`. Будь-який вихід з циклу проходить через нього, тож історія пишеться завжди. Коли запуск зупинив ліміт чи помилка, у файл іде той текст, який побачив користувач: «Зупинився після 8 кроків...». Інакше наступного разу модель не знала б, що попередня задача обірвалась.

Зверни увагу: у файл іде обрізаний `kept.messages` плюс новий обмін. Найстаріші повідомлення, які не влізли в ліміт, з файла теж зникають.

Нова подія в trace:

```ts
trace('history', { loaded: history.length, kept: kept.messages.length, trimmed: kept.trimmed });
```

`loaded` = скільки повідомлень лежало у файлі, `kept` = скільки пішло в запит, `trimmed` = скільки найстаріших відкинули.

### Модель має знати, що памʼять є: `src/agent.ts`

```ts
'Memory: earlier messages of this chat are your conversation history. Answer questions about what the user said before directly from them, without tools. Notes are only for what the user asks to save.',
```

Памʼять у харнесі вже працює, але модель про неї нічого не знає. Вона бачить у запиті минулі повідомлення, а в `system` написано, що вона асистент нотаток. На живому прогоні на `gpt-4.1-mini` це вилізло так: на «нагадай, як мене звати» модель викликала `searchNotes` з імʼям, отримала порожній список і відповіла, що імені в нотатках немає і що вона «не зберігає інформацію з історії між сесіями». Історія при цьому лежала в запиті двома повідомленнями вище.

Код дає моделі памʼять, а цей рядок каже, що вона в неї є і як нею користуватись. Про минулу розмову відповідати з історії, без тулів. Нотатки лише для того, що користувач просить зберегти.

## Спробуй

- У веб-чаті з `chat id` = `web`: «Мене звати Оля», потім «Як мене звати?». Тепер бот памʼятає. У trace другого запуску рядок «Історія чату» пише, скільки минулих повідомлень іде в запит. Без тулів це «2 минулих повідомлень іде в запит», а якщо модель вирішила зберегти імʼя нотаткою, буде 4. У першому запуску там «Перше повідомлення в цьому чаті: минулого немає».
- Розгорни «Запит до моделі» другого запуску: у `messages` спершу минулий обмін, потім нове питання.
- Відкрий `.data/history/web.json`. Там уся розмова з ролями `user`, `assistant` і `tool`, разом з викликами тулів.
- Зміни `chat id` на `petro` і спитай «Як мене звати?». Цей чат Олі не знає, у нього свій файл.
- Перезапусти `npm run web` і повернись у чат `web`. Памʼять на місці.
- Те саме з термінала. CLI завжди пише в чат `cli`, тож два окремі процеси памʼятають один одного:

  ```bash
  npm run cli -- "Мене звати Оля"
  npm run cli -- "Як мене звати?"
  ```

  Другий запуск друкує рядок на кшталт `історія чату: 2 повідомлень`.
- У Telegram те саме: напиши боту імʼя, потім спитай. Попроси сусіда спитати «Як мене звати?» у твого бота.

Обрізання історії руками побачити довго: треба більше 40 повідомлень в одному чаті, а обмін з тулом займає чотири. Його перевіряє тест.

## Відома межа

Історія читається на старті запуску і перезаписується в кінці. Якщо два запуски в одному чаті йдуть одночасно, той, що закінчився пізніше, затре обмін першого. Telegram через grammY обробляє повідомлення по черзі, тож там цього не буває. У вебі буває: два запити на `/api/chat` з тим самим `chat id` з двох вкладок підуть паралельно. Для воркшопу ми з цим живемо. У справжньому боті тут потрібна черга на чат або база з блокуванням.

## Перевірка

```bash
npm test -- --step 07
```

- `07 памʼять розмови: другий запуск у тому ж чаті бачить перший, сусідній чат ні`: у другому запиті минулий обмін стоїть перед новим питанням, у чужому чаті його немає, `loaded` по запусках `0, 2, 0`.
- `07 історія лежить у файлі й переживає перезапуск`: файл читається напряму, ролі `user, assistant, user, assistant`.
- `07 у історію йдуть і виклики тулів, і їхні результати, і фінальна відповідь`: ролі `user, assistant, tool, assistant`, у файлі є id виклику.
- `07 обрізання історії ріже лише перед повідомленням користувача`: для будь-якого ліміту від 1 до 20 історія починається з `user`, і жодного результату тула без його виклику.
- `07 chatId з вебу не виводить файл історії за межі теки`: `../../evil` дає файл усередині `HISTORY_DIR`.
- `07 зіпсований файл історії не валить чат: відкладаємо вбік і починаємо заново`: запуск закінчується з `final`, поруч лежить `broken.json.broken-…`, а нова історія містить лише цей обмін.
- `07 модель знає, що минулі повідомлення чату теж її памʼять`: у `system` агента є рядок про історію чату як памʼять.

## Якщо не так

- Модель шукає імʼя в нотатках замість історії: у trace на питання «Як мене звати?» стоїть «Модель просить тул» `searchNotes` з `query` на кшталт `"Оля"`, «Результат» порожній (`[]`), а відповідь каже, що імені немає. Перевір, що в `system` у «Запит до моделі» є рядок `Memory: ...`. Якщо є, а модель однаково йде в тул, спитай прямо «що я тобі казав про своє імʼя?» або візьми іншу модель.

- Бот однаково не памʼятає: перевір, що `chat id` у веб-чаті той самий в обох повідомленнях, і що ти перезапустив `npm run web` після `npm run step 07`.
- Бот памʼятає те, що ти хотів забути: зупини `npm run web` і видали `.data/history/<chatId>.json`. Або візьми у веб-чаті новий `chat id`.
- Запити стали великими і Groq Free відповідає `Request too large`: історія займає місце в кожному запиті. Почни новий чат так само, як у пункті вище.
- Бот раптом забув усю розмову, у trace «Перше повідомлення в цьому чаті: минулого немає», а в терміналі `Історія чату … не читається (…), відклав у ….`: файл історії був зіпсований, наприклад після ручної правки. `loadHistory` не валить через нього запуск. Він перейменовує файл у `<chatId>.json.broken-<час>` і починає чат з чистої історії. Старий файл лежить поруч у `.data/history/`. Хочеш повернути розмову: полагодь JSON і перейменуй файл назад, поки `npm run web` зупинений.
