# 06. Telegram

[Усі етапи](README.md) · [Попередній](05-failures.md) · [Наступний](07-history.md)

**Гілка:** `step-06`. Перейти: `npm run step 06`, далі перезапусти `npm run web`. Потрібен `TELEGRAM_BOT_TOKEN` у `.env`.

## Що додаємо і навіщо

Бот нотаток виходить з браузера в Telegram. Харнес при цьому не змінюється ні на рядок: канал лише приймає текст, викликає той самий `runAgent` і надсилає відповідь назад. Уся логіка циклу, тулів, лімітів і повторів лишається в одному місці.

Веб і Telegram працюють в одному процесі й пишуть в одну шину trace. Тому запуск з Telegram зʼявляється у веб-харнесі наживо, поруч із запусками з браузера. Без токена `npm run web` працює як раніше і пише в термінал «Telegram вимкнено».

`chatId` бере код з даних Telegram. Модель його не бачить і не вибирає. Кожен, хто пише боту, отримує свої нотатки, бо в нього свій chat id. Команда `/start` показує цей id, на етапі 09 ти запишеш свій в `OWNER_CHAT_ID`.

Памʼяті розмови тут ще немає. Кожне повідомлення в Telegram = нова задача з чистим масивом `messages`. Нотатки зберігаються, бо лежать у файлі, а от що ти написав хвилину тому, бот не памʼятає. Це етап 07.

## Код

### Бот: `src/channels/telegram.ts`

```ts
const telegramLimit = 4_000; // Telegram приймає до 4096 символів в одному повідомленні.

// /start показує chat id. Він знадобиться, щоб призначити власника бота (OWNER_CHAT_ID).
bot.command('start', async ctx => {
  console.log('Telegram chat id:', ctx.chat.id);
  await ctx.reply(`Привіт! Твій chat id: ${ctx.chat.id}`);
});

bot.on('message:text', async ctx => {
  await ctx.replyWithChatAction('typing').catch(() => {});
  // chatId бере код з даних Telegram. Модель його не бачить і не вибирає.
  const result = await runAgent(agent, ctx.message.text, { channel: 'telegram', chatId: String(ctx.chat.id) });
  for (let offset = 0; offset < result.text.length; offset += telegramLimit) {
    await ctx.reply(result.text.slice(offset, offset + telegramLimit));
  }
});
```

Довгу відповідь ріжемо на шматки по 4000 символів. `try/catch` навколо `runAgent` не потрібен: з етапу 05 він сам ловить помилки моделі й повертає текст з причиною. Помилки самого Telegram, наприклад обрив мережі, ловить `bot.catch` і пише в термінал, процес від них не падає.

### Зрозумілі помилки запуску

```ts
.catch(error => {
  if (error instanceof GrammyError && error.error_code === 409) {
    // Telegram віддає одне з'єднання на токен: другий процес обриває перший, і той зупиняється назавжди.
    console.error('Telegram 409 Conflict: з цим токеном запущено ще один процес, він перехопив повідомлення. Залиш один процес і перезапусти його.');
  } else if (error instanceof GrammyError && error.error_code === 401) {
    console.error('Telegram 401: токен неправильний. Візьми новий у @BotFather.');
  }
  // ...
});
```

### Один процес: `src/main.ts`

```ts
// Один процес: веб-харнес і Telegram пишуть в одну шину trace.
const server = startWeb(agent);
const bot = startTelegram(agent);

// Ctrl+C: спершу чемно зупиняємо бота, інакше Telegram надішле останнє повідомлення ще раз.
const shutdown = async () => {
  await bot?.stop();
  server.close();
  process.exit(0);
};
process.once('SIGINT', shutdown);
process.once('SIGTERM', shutdown);
```

`bot.stop()` встигає сказати Telegram, які повідомлення вже оброблено. Без цього після перезапуску бот отримає останнє повідомлення вдруге і, наприклад, збереже ту саму нотатку двічі. А перезапускати ти будеш після кожного етапу.

## Спробуй

```bash
npm run web
```

У терміналі має бути `Telegram: бот @твій_бот слухає повідомлення.` Відкрий бота в Telegram:

1. `/start`. Бот відповість твоїм chat id. Запиши його, на етапі 09 він стане `OWNER_CHAT_ID`.
2. «Запамʼятай: у пʼятницю реліз о 15:00». У веб-харнесі зʼявиться запуск з позначкою `Telegram · chat <твій id>` і всіма кроками. У `.data/notes.json` нотатка з твоїм Telegram chat id.
3. «Що в мене з релізом?». Бот знайде нотатку через `searchNotes`.
4. «Мене звати Оля», потім «Як мене звати?». Бот не знає: памʼяті розмови ще немає.
5. Попроси сусіда написати твоєму боту «Що в мене з релізом?». Його запуск буде з іншим chat id, і твоєї нотатки він не побачить.

## Перевірка

```bash
npm test -- --step 06
```

Тести ганяють бота без мережі: виклики Telegram API перехоплені.

- `06 /start відповідає chat id`: відповідь містить id, модель не викликали.
- `06 повідомлення з Telegram іде в той самий цикл і trace`: подія `start` з `channel: 'telegram'` і правильним `chatId`.
- `06 довга відповідь ріжеться на шматки до 4000 символів`: 9000 символів приходять трьома повідомленнями.

## Якщо не так

- `Telegram вимкнено: TELEGRAM_BOT_TOKEN порожній.`: встав токен у `.env` і перезапусти.
- `Telegram 409 Conflict`: з цим токеном запущено ще один процес. 409 приходить тому, хто стартував раніше, і він замовкає. Найчастіше це другий `npm run web` в іншому терміналі. Зупини зайвий і перезапусти той, що лишився.
- `Telegram 401`: токен неправильний. Скопіюй ще раз або візьми новий у @BotFather через `/token`.
- Бот довго мовчить, поки ти пишеш кілька повідомлень: grammY у такому запуску обробляє повідомлення по черзі. Поки агент працює над одним, наступні чекають.
- Бот відповідає «Модель не відповіла: ...»: це помилка моделі після повторів, частіше за все ліміт Groq Free. Деталі в trace.
- У груповому чаті всі учасники мають один chat id, тож і нотатки в групі спільні.
