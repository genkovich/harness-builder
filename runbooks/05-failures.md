# 05. Збої: помилка як дані, retry, обрізана відповідь

[Усі етапи](README.md) · [Попередній](04-limits.md) · [Наступний](06-telegram.md)

**Гілка:** `step-05`. Перейти: `npm run step 05`, далі перезапусти `npm run web`.

## Що додаємо і навіщо

До цього етапу будь-яка помилка валила запуск: хтось зіпсував `.data/notes.json`, диск не дав записати файл, Groq відповів 429. Запуск висів у trace як «виконується», бо подію `stop` ніхто не писав. Тепер розбираємо збої по типах, і для кожного своя реакція.

Помилка тула стає даними. Харнес ловить її, пише `tool_error` і віддає моделі `{ error: "..." }` як результат того самого виклику. Модель читає її і пробує інакше або пояснює користувачу, що не вийшло. У system prompt для цього зʼявився рядок `Errors: ...`.

Помилки моделі повторюємо самі. AI SDK вміє повторювати під капотом, але тоді повторів не видно. Ми вимикаємо їх (`maxRetries: 0`) і повторюємо в своєму коді лише те, що може пройти з другої спроби: 429 і 5xx. Чекаємо стільки, скільки просить `Retry-After`, але не більше 30 секунд, і пробуємо ще до двох разів. «Request too large» теж приходить як 429, але той самий запит не пройде і вдруге, тож його не повторюємо.

Обрізана відповідь моделі (`finishReason: 'length'`) означає, що модель уперлась у `maxOutputTokens`. Аргументи тулів у такій відповіді можуть бути неповні: уяви `saveNote`, у якого текст нотатки обірвався на півслові. Тож жоден тул з неї не виконуємо і зупиняємось з причиною `truncated`. Усе, що не врятували повтори, ловить зовнішній `catch` і зупиняє запуск з причиною `error`.

## Код

### Помилка тула = результат: `src/harness.ts`

```ts
try {
  // Аргументи не пройшли схему: виконавцю такий виклик не передаємо.
  if (call.invalid) {
    throw call.error;
  }

  trace('tool_start', { ...base, input: call.input });
  // await потрібен, щоб catch перехопив і помилку асинхронної функції.
  const output = await agent.runTool(call.toolName, call.input, run);
  // clip і tool_result як на етапі 04
} catch (error) {
  // Помилка тула = дані для моделі. Вона прочитає й спробує інакше.
  const message = error instanceof Error ? error.message : String(error);
  trace('tool_error', { ...base, error: message });
  return { error: message };
}
```

Зверни увагу на `await` перед `agent.runTool`. Без нього функція повернула б проміс, і його відмову `catch` уже не побачив би. Невалідні аргументи з етапу 03 тепер теж просто кидають помилку (`throw call.error`) і потрапляють у той самий `catch`.

### Що повторювати

```ts
// Повторюємо лише те, що може пройти з другої спроби: 429 і 5xx.
function retryDelay(error: unknown, attempt: number, limits: Limits): number | null {
  if (attempt >= limits.maxRetries || !APICallError.isInstance(error)) {
    return null;
  }
  const status = error.statusCode ?? 0;
  // «Request too large» теж 429, але той самий запит не пройде і вдруге.
  if (/too large/i.test(error.message) || (status !== 429 && status < 500)) {
    return null;
  }
  const seconds = Number(error.responseHeaders?.['retry-after']);
  const wait = Number.isFinite(seconds) && seconds >= 0 ? seconds * 1_000 : 1_000 * 2 ** attempt;
  return Math.min(wait, limits.maxRetryWaitMs);
}
```

Без `Retry-After` чекаємо 1 секунду, потім 2. Кожен повтор пише подію `retry` зі статусом і часом очікування.

### Обрізана відповідь

```ts
// Обрізана відповідь: аргументи тулів можуть бути неповні, тож нічого не виконуємо.
if (reply.finishReason === 'length') {
  return stop('truncated', 'Відповідь моделі обрізано на maxOutputTokens. Тули з неї не виконую, спробуй коротшу задачу.');
}
```

Перевірка стоїть до перевірки `toolCalls`, тож навіть повний на вигляд виклик з обрізаної відповіді не виконається.

## Спробуй

- Зламай файл нотаток. Спершу скопіюй його, якщо там щось потрібне, потім:

  ```bash
  echo '{ зламаний json' > .data/notes.json
  ```

  Попроси «Покажи мої нотатки». `searchNotes` упаде на `JSON.parse`. У trace буде «Помилка тула» з текстом `SyntaxError` і підписом «Помилка пішла моделі як результат.», а модель відповість, що нотатки прочитати не вдалося. Запуск закінчиться нормально, з причиною «фінальна відповідь». Поверни файл: `echo '[]' > .data/notes.json` або свою копію.
- На Groq Free надішли кілька задач поспіль. Коли впреш у хвилинний ліміт, у trace зʼявиться «Повтор» з часом очікування.
- Попроси щось дуже довге, наприклад «Напиши детальний план переїзду на 3000 слів». Модель упреться в 1000 токенів, і запуск зупиниться з причиною «обрізано».

## Перевірка

```bash
npm test -- --step 05
```

- `05 помилка тула повертається моделі як дані, цикл живе далі`: файл нотаток зіпсовано, `searchNotes` дає `tool_error`, модель бачить помилку в наступному запиті, зупинка `final`.
- `05 429 з Retry-After: чекаємо й повторюємо, повтор видно в trace`: два запити, подія `retry` зі статусом 429 і `waitMs: 0`, бо тест просить `Retry-After: 0`.
- `05 «Request too large» не повторюємо: той самий запит не пройде`: один запит, зупинка `error`.
- `05 обрізана відповідь моделі: тули з неї не виконуємо`: `truncated`, тул не запускали жодного разу.

## Якщо не так

- Зупинка «помилка» з `Request too large`: запит не влазить у хвилинний ліміт Groq Free. Дай коротшу задачу або візьми іншого провайдера.
- Повтори є, але запуск однаково падає: обидва повтори вичерпано, або Groq просив чекати довше, ніж наші 30 секунд. Почекай хвилину й надішли задачу ще раз.
- Часто «обрізано»: 1000 токенів на відповідь мало для цієї задачі. Розбий її на менші. На Groq ще перевір `GROQ_REASONING`: з вищим зусиллям міркування зʼїдають більшу частину цих токенів.
