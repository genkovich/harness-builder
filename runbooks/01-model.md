# 01. Модель: один запит

[Усі етапи](README.md) · [Попередній](00-start.md) · [Наступний](02-loop.md)

**Гілка:** `step-01`. Перейти: `npm run step 01`, далі перезапусти `npm run web`.

## Що додаємо і навіщо

Замість ехо харнес робить рівно один запит до моделі й повертає її текст. Циклу ще немає, тулів теж. Цей етап потрібен, щоб побачити, з чого складається запит і що приходить назад.

Роль агента лежить у `src/agent.ts` ще з етапу 00, тож у diff її не буде. Але тільки тепер вона доходить до моделі. Поки це два рядки `system`: особистий асистент нотаток у Telegram, відповідає українською. Нотаток він ще не вміє, тули прийдуть на етапі 02.

Головна думка етапу записана коментарем у коді: уся «памʼять» моделі = масив `messages`. Модель не памʼятає попередніх задач і не бачить нічого, крім того, що харнес поклав у запит. У trace тепер дві нові події: `request` перед запитом і `response` після. У `response` є токени з `usage`, ціна кроку і сирий HTTP-запит, який AI SDK відправив провайдеру.

Якщо провайдер не повідомив якесь число, харнес пише `null`, і веб-харнес показує «н/д». Нуль означав би «нуль токенів» або «безкоштовно», а це інша інформація.

## Код

### Роль агента: `src/agent.ts` (без змін з етапу 00)

```ts
// Інструкції моделі англійською, відповідь користувачу українською.
const system = [
  'Role: a personal notes assistant in Telegram. The user saves notes and asks about them.',
  'Answer in Ukrainian, plain text.',
].join('\n');
```

Далі на кожному етапі сюди додаватиметься рядок-два, і в diff буде видно, що саме.

### Запит: `src/harness.ts`

```ts
// Уся «памʼять» моделі = цей масив. Що в нього не поклали, того вона не бачить.
const messages: ModelMessage[] = [{ role: 'user', content: task }];

const reply = await generateText({
  model: agent.model.model,
  system: agent.system,
  messages,
  maxOutputTokens,
  abortSignal: AbortSignal.timeout(60_000),
  // Зберегти сирий HTTP-запит, щоб показати його у веб-trace.
  include: { requestBody: true },
});
```

`maxOutputTokens` = 1000: на Groq Free запит із більшим `max_tokens` не проходить. `AbortSignal.timeout(60_000)` не дає зависнути на моделі довше хвилини.

### Що пишемо в trace

```ts
const costUsd = costOf(agent.model, reply.usage);
trace('response', {
  turn: 1,
  text: reply.text,
  toolCalls: [],
  finishReason: reply.finishReason,
  usage: usageOf(reply.usage),
  costUsd,
  totalCostUsd: costUsd,
  body: reply.request.body ?? null,
});
```

`usageOf` перекладає `usage` з AI SDK у чотири числа: `input`, `output`, `cacheRead`, `cacheWrite`. Кожне може бути `null`.

### Модель і ціна: `src/model.ts`

```ts
// Ділимо лише по першому «/»: у groq/qwen/qwen3.8-27b назва моделі сама містить слеш.
const slash = spec.indexOf('/');
```

Ціну рахує `costOf`: токени запиту без кешованих за повною ціною, кешовані за ціною кешу, токени відповіді за своєю ціною. Ціни лежать у таблиці лише для `openai/gpt-4.1-mini` і `openai/gpt-4.1`. Groq Free коштує нуль. Для решти ціна `null`, поки не задаси `PRICE=вхід,кеш,вихід` у `.env`.

Ще одна деталь для Groq:

```ts
// Qwen на Groq міркує перед відповіддю, і міркування їдять ті самі 1000 вихідних токенів.
// Низьке зусилля лишає місце для відповіді й tool call. GROQ_REASONING=none|default|low|medium|high.
```

Типово `low`. Якщо відповіді обриваються на півслові, це перше, що варто покрутити.

## Спробуй

У веб-харнесі спитай «Що ти вмієш? Два речення.» Розгорни крок і подивись:

- «Запит до моделі»: `system` і масив `messages` з одним повідомленням.
- Відповідь моделі: токени на вхід і вихід, ціна кроку або «ціна н/д».
- «сирий HTTP-запит до провайдера»: так виглядає JSON, який пішов у Groq чи OpenAI.

Потім напиши «Мене звати Оля» і одразу «Як мене звати?». Модель не знає: кожна задача починається з нового масиву `messages`. Памʼять розмови зробимо самі на етапі 07.

## Перевірка

```bash
npm test -- --step 01
```

- `01 один запит: текст моделі, сирий запит, токени й ціна в trace`: рівно один запит, у trace є `system`, задача, токени, ціна і `body`.
- `01 MODEL ділиться лише по першому слешу`: `groq/qwen/qwen3.8-27b` дає провайдера `groq` і модель `qwen/qwen3.8-27b`.
- `01 Groq: низьке зусилля міркувань, щоб відповідь влізла в 1000 токенів`: у запиті до Groq стоїть `reasoning_effort: "low"` і `max_tokens: 1000`.
- `01 невідома ціна = null, нуль не підставляємо`: модель без ціни в таблиці отримує `price: null`.

Вручну: модель відповідає в чаті, у trace видно токени.

## Якщо не так

- «Сервер не прийняв задачу. HTTP 500: ...» в чаті: модель повернула помилку, після двокрапки її текст. Найчастіше порожній ключ або 429 на Groq Free. Зачекай хвилину. AI SDK уже сам повторює 429 кілька разів, але в trace цього не видно. Свої видимі повтори зробимо на етапі 05.
- Запуск висить як «виконується»: це той самий випадок. Помилку моделі поки ніхто не ловить, тож подія `stop` не приходить.
- Вартість «н/д»: для цієї моделі немає ціни. Задай `PRICE` у `.env` і перезапусти `npm run web`.
