# 00. Старт: веб-харнес, trace, doctor

[Усі етапи](README.md) · [Наступний](01-model.md)

**Гілка:** `step-00`. Перейти: `npm run step 00`, далі `npm run web`.

## Що додаємо і навіщо

Перш ніж підключати модель, ставимо те, через що будемо на неї дивитись. Харнес на цьому етапі нічого не вміє: `runAgent` повертає задачу назад з приставкою «Ехо». Зате вже працює все навколо: веб-чат, шина подій trace, запис подій у файли, doctor і CLI.

Trace тут головний інструмент. Кожен крок харнесу пише подію: почав задачу, спитав модель, отримав відповідь, виконав тул, зупинився. Події йдуть одночасно у файл `.data/trace-<канал>.jsonl` і на шину в памʼяті процесу. Веб-харнес слухає шину й малює кожну подію наживо. Далі на кожному етапі ти побачиш нові типи подій, і саме по них видно, що додав етап.

Сторінка й API слухають лише `127.0.0.1`. Харнес має доступ до ключів і нотаток, тож світити ним у мережу не будемо.

## Код

### Харнес-заглушка: `src/harness.ts`

```ts
// Етап 00: харнес ще нічого не вміє, лише повертає задачу назад.
// Веб-чат, trace і doctor уже працюють. Модель підключимо на етапі 01.
export async function runAgent(agent, task, where) {
  const run: RunInfo = { runId: randomUUID().slice(0, 8), ...where };
  const trace = tracer(run);
  trace('start', { task, model: agent.model.id });

  const text = `Ехо: ${task}`;
  trace('stop', { reason: 'echo', text, turns: 0, costUsd: null });
  return { runId: run.runId, reason: 'echo', text };
}
```

Один запуск = одна задача з власним `runId`. `where` каже, звідки прийшла задача: канал (`web`, `telegram`, `cli`) і `chatId`. Ці поля потрапляють у кожну подію, тож веб-харнес може розкласти події по запусках. `chatId` ще стане в пригоді: за ним бот розкладатиме нотатки, історію розмови і права власника.

### Одна подія, два місця: `src/trace.ts`

```ts
export function emit(run: RunInfo, type: string, data: Record<string, unknown> = {}) {
  const event: TraceEvent = { ...data, type, ...run, at: new Date().toISOString() };
  remember(event);
  try {
    mkdirSync(traceDir(), { recursive: true });
    appendFileSync(join(traceDir(), `trace-${run.channel}.jsonl`), JSON.stringify(event) + '\n');
  } catch (error) {
    console.error('Не вдалося записати trace:', error instanceof Error ? error.message : error);
  }
  bus.emit('event', event);
  return event;
}
```

Файл переживає перезапуск, шина дає живу картинку. Якщо запис у файл не вдався, харнес не падає: trace допомагає дивитись, і зупиняти через нього роботу агента не варто.

### Веб: `src/channels/web.ts`

```ts
if (request.method === 'POST' && url.pathname === '/api/chat') {
  // ...
  // У веб-чаті chatId задаєш ти сам: так видно, що бачить власник, а що чужий чат.
  const chatId = String(body.chatId ?? 'web').trim() || 'web';
  const result = await runAgent(agent, text, { channel: 'web', chatId });
  return json(response, 200, { text: result.text, reason: result.reason });
}
```

`POST /api/chat` відповідає, коли задача вже закінчилась. Події тим часом летять окремо через Server-Sent Events на `GET /api/events`: спершу останні події з файлів, потім живі. Тому оновлення сторінки trace не губить. Поле `chat id` у веб-чаті задаєш сам. На етапі 07 з ним буде видно, що в кожного чату своя памʼять, а на етапі 09 що бачить власник і що чужий чат.

## Спробуй

```bash
npm run web
```

Відкрий http://localhost:3000 і напиши «Привіт». У чаті прийде «Ехо: Привіт», справа зʼявиться запуск з подіями `start` і `stop` і зупинкою «ехо». Панель «Контекст» поки порожня, вона оживе на етапі 10.

Те саме з термінала:

```bash
npm run cli -- "Привіт"
```

CLI пише свій trace у `.data/trace-cli.jsonl`. Це окремий процес, але веб-харнес стежить за файлами trace інших процесів, тож запуск зʼявиться у вебі наживо з позначкою `CLI`.

## Перевірка

```bash
npm test -- --step 00
```

Три тести без мережі:

- `00 веб бачить наживо запуски з інших процесів, наприклад CLI`: подія, яку інший процес дописав у свій файл trace, доходить до веб-харнесу.
- `00 веб-харнес: сторінка, info, чат і SSE з подіями`: сторінка відкривається, `/api/info` віддає модель, чат повертає текст, а SSE віддає вже записані події `start` і `stop`.
- `00 статика не віддає файли поза web/`: запит `/..%2F.env` отримує 404.

Вручну: `npm run doctor` зелений, у браузері ехо і два рядки trace.

## Якщо не так

- `порт 3000 зайнятий`: постав `PORT=3001` у `.env` і відкрий http://localhost:3001.
- Сервер не стартує з `MODEL має бути у форматі провайдер/модель`: модель тут ще не викликаємо, але `MODEL` читається вже на старті. Візьми рядок із [README](../README.md#3-ключ-моделі).
- Справа «Запусків ще немає» після повідомлення: перевір рядок «звʼязок» біля назви. Якщо там «перепідключаюсь…», сервер упав, причина в терміналі.
