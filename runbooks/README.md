## Баги каркаса з дня 1

Першого дня ми розбирали каркас агента (Лістинг 3) і знайшли в ньому баги. Тут кожен закриваємо в коді на своєму етапі:

- [Етап 02](02-loop.md): цикл закінчується явним `return`. У каркасі ліміт кидав `raise StopIteration` усередині `async def`, і Python перетворював це на `RuntimeError: coroutine raised StopIteration`.
- [Етап 03](03-tools.md): у кожного тула схема аргументів на Zod з межами. У каркасі тули мали лише назву й опис, модель не знала, які аргументи передавати.
- [Етап 07](07-history.md): стару історію чату обрізаємо лише перед повідомленням користувача. У каркасі компакція брала хвіст історії, і він міг початися з результату тула без його виклику. Такий запит API відхиляє.
- [Етап 09](09-permissions.md): у боті немає `bash`. Каркас давав моделі `bash` з `shell=True`, а нашому боту може написати будь-хто.

## Як працюють тести

Тести лежать у `test/NN-*.test.mjs`, номер у назві файла і в назві тесту = етап. Замість моделі там скриптована модель з `ai/test`: вона по черзі повертає заготовлені відповіді й записує кожен запит, який отримала. Нотатки, історію чатів і trace кожен тестовий файл пише у свою тимчасову теку, тож твій `.data/` тести не чіпають. Виклики Telegram API перехоплені. Тому тести не ходять у мережу і не потребують ключа.

```bash
npm test -- --step 04   # лише етап 04
npm test                # усе, що є в поточній гілці
```

Тести перевіряють механіку харнесу. Як поведеться жива модель, дивимось руками у веб-харнесі й у Telegram.
