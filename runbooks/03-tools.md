# 03. Тули: searchNotes, схеми, id

[Усі етапи](README.md) · [Попередній](02-loop.md) · [Наступний](04-limits.md)

**Гілка:** `step-03`. Перейти: `npm run step 03`, далі перезапусти `npm run web`.

## Що додаємо і навіщо

Схема тула це контракт між моделлю і нашим кодом. Другий баг каркаса з дня 1 був саме тут: тули мали тільки назву й опис, без схеми аргументів, і модель мусила вгадувати, що передати. На етапі 02 схема в нас уже є, але слабка: `z.string()` пропустить порожню нотатку або текст на мегабайт. Тепер у кожного поля межі.

AI SDK перевіряє аргументи за схемою ще до нашого коду. Якщо не пройшли, виклик приходить з позначкою `invalid`. Такий виклик виконавцю не передаємо. Модель отримує помилку як результат свого виклику, з тим самим id, і може спробувати ще раз.

Другий тул `searchNotes` шукає нотатки за текстом. Шукає лише серед нотаток свого чату: `chatId` знову підставляє код, у схемі його немає. Порожній запит повертає всі нотатки чату, і це знадобиться стендапу на етапі 08.

## Код

### Схеми з межами: `src/tools/notes.ts`

```ts
// Схема = контракт тула. SDK перевіряє аргументи моделі ще до нашого коду.
const noteInput = z.object({ text: z.string().trim().min(1).max(maxNoteCharacters) });
const searchInput = z.object({ query: z.string().max(200).default('') });
```

`maxNoteCharacters` = 2000. Межі описують, що осмислене для нотатки: непорожній текст і не роман. Запит пошуку можна не передавати зовсім, тоді він порожній.

### Пошук лише у своєму чаті

```ts
export function searchNotes(chatId: string, query = '') {
  const search = query.trim().toLowerCase();
  // Спершу лише свій чат, потім пошук за текстом. Порожній запит повертає всі.
  return readNotes().filter(note => note.chatId === chatId && note.text.toLowerCase().includes(search));
}
```

Опис тула для моделі: `"Find the user's saved notes that contain the query. An empty query returns all notes with their dates."` Модель знає, що з порожнім запитом отримає все.

### Невалідний виклик не доходить до виконавця: `src/harness.ts`

```ts
const base = { turn, id: call.toolCallId, name: call.toolName };
// Аргументи не пройшли схему: виконавцю такий виклик не передаємо, модель отримує помилку.
if (call.invalid) {
  const message = call.error instanceof Error ? call.error.message : String(call.error);
  trace('tool_error', { ...base, error: message });
  return { error: message };
}
```

З цього етапу в trace зʼявляється `tool_error`. Цикл від нього не зупиняється: помилка йде моделі в `tool_result`.

У `system` рядок про нотатки тепер згадує обидва тули: `Notes: use saveNote and searchNotes. Never claim a note is saved or found without a tool result.`

## Спробуй

- Збережи дві-три нотатки, потім спитай «Що в мене з релізом?». У trace буде `searchNotes` з `query` на кшталт `"реліз"`, у «Результат» знайдені нотатки.
- «Покажи всі мої нотатки». Модель має викликати `searchNotes` з порожнім `query`.
- Зміни `chat id` у веб-чаті на інший і спитай про реліз ще раз. Нотаток іншого чату пошук не бачить.
- Подивись на id: виклик у відповіді моделі і «Результат» під ним мають той самий id.
- Схему найлегше побачити в тестах. Жива модель рідко шле порожню нотатку, хоча можна спробувати «Збережи порожню нотатку». Якщо вона так і зробить, у trace буде «Помилка тула» з текстом від Zod, а наступним кроком модель або виправить виклик, або пояснить, що порожнє не зберігає.

## Перевірка

```bash
npm test -- --step 03
```

- `03 searchNotes шукає лише в нотатках свого чату`: нотатка іншого чату з тим самим словом у результат не потрапляє, порожній запит дає всі нотатки чату.
- `03 у трейсі виклик і результат мають той самий id`.
- `03 аргументи не за схемою не доходять до виконавця`: `text: ''` дає `tool_error`, `tool_start` не було, файл не змінився, модель бачить помилку в наступному запиті.

## Якщо не так

- Модель знову і знову шле ті самі неправильні аргументи: подивись текст помилки в «Помилка тула». Повідомлення Zod англійською, моделі його зазвичай вистачає. Якщо ні, бери модель сильнішу з тулами.
- Модель відповідає «нотаток немає», не викликавши `searchNotes`: рядок `Never claim ... found without a tool result` у `system` це забороняє, але модель може не послухатись. Попроси прямо «пошукай у нотатках».
- Пошук не знаходить нотатку, яка точно є: перевір `chat id`. Нотатка з веб-чату `web` і нотатка з чату `olia` лежать в одному файлі, але пошук кожного чату бачить лише свої.
